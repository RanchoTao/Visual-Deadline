# 微信通讯录导入可行性调研

## 结论

Visual Deadline 当前是浏览器运行的 React Web/PWA。标准 Web 权限不能读取微信好友列表；微信开放平台面向网站/公众号/小程序的公开授权能力也不提供个人微信好友通讯录导出。因此，本轮不提供“微信一键导入”假入口，也不采用逆向协议、读取或解密客户端数据库、模拟登录、注入客户端等不可维护且高风险方案。

## 可实施方案

1. **vCard（已实现）**：用户从系统通讯录或可信工具主动导出 `.vcf`，在 Social 页面明确选择文件。VD 只解析 `FN` 姓名字段。
2. **CSV（已实现）**：用户选择 `.csv`，当前 MVP 把首列作为姓名并去重；后续应增加列映射预览。
3. **Contact Picker API（候选）**：仅部分 Android Chromium、安全上下文和用户手势下可用，且必须逐次显式授权，不适合作为唯一方案。
4. **微信官方能力（持续观察）**：只有当微信开放平台未来提供适用于普通好友通讯录、具备明确用户授权与合规条款的 API 时才接入。

## 隐私与合规

导入必须由用户主动选取文件；界面应在写入前提供字段预览和去重。联系人属于个人信息，云同步需沿用 user-owned RLS、最小化采集、支持删除与导出，并在隐私政策中说明用途和保留期限。不得上传原始文件作为隐式备份。

## 推荐路线与后续工作

以 vCard 为主、CSV 为补充；增加解析预览、字段映射、错误行报告和批量撤销。能力检测到 `navigator.contacts.select` 时，可渐进增强 Contact Picker。微信来源仅显示技术限制说明，不显示不可用的假按钮。
