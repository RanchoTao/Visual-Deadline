# Life OS：Life Map 与 Timeline

## 两种视图，各自回答一个问题

**Life Map（Path Map）**回答“我的路线怎样发展？”它按演化与因果顺序从左向右阅读，不把节点距离伪装成时间长度。**Timeline**回答“工作在真实日期上怎样并行？”它只使用一套连续日期坐标；日、周、月、季度只是同一数据的缩放。

## Life Map 语义

- **主线**是当前主要推进的路线，位于最明确的阅读通道。
- **分支**从一个已有节点产生，代表探索、备选或并行项目。
- **节点**可表示决定、成果、阶段或里程碑；标题完整换行，日期仅作说明。
- **合流**把支线成果连接回另一个节点；动态连接用于表达活跃演化或合流。
- **当前位置**使用 VD 红色和文字双重标识。每次只设一个当前节点。
- **暂停 / 放弃**使用虚线、降低透明度和文字状态；**未来规划**使用浅灰背景；完成也有明确文字状态。

用户可筛选领域和路线状态、平移缩放、适应画布、查看或编辑节点、从节点创建分支、设置当前位置、暂停/恢复路线和指定合流目标。修改写入现有本地 Life OS 数据，不是临时演示。

## Timeline 甘特排期

左侧按目标/项目分组，可折叠并显示状态、进度及已有负责人；右侧每项占独立行，因而并行任务不会互相覆盖。任务条的长度映射开始和截止日期，条内浅色填充表示完成进度。菱形表示只有一个日期的目标里程碑，`↳` 表示存在前置依赖，红色竖线根据当前真实日期计算“今天”。延期、阻塞、完成同时使用颜色和文字表达。

没有截止日期的任务不会被猜测位置，而会进入底部**未排期**区。日、周、月、季度切换只改变每日像素宽度；横向滚动在表头与各行同步。长期人生阶段不再与本周任务共享伪统一横轴；以后若恢复人生阶段，将作为独立长期概览。

## 共享数据与兼容性

`projectLifeData` 是两个投影的统一 adapter：读取现有 `Goal`、`Task`、Life OS 节点和依赖，生成路径节点与排期行。目标标题、状态和日期因此来自原数据；任务只在 Timeline 出现，除非用户显式建立路径节点。旧节点没有路径字段时会安全映射到主线，不删除或重写旧数据。

任务可选增加 `startDate`、`dependencyIds`、`assignee`，目标可选增加 `startDate`；Life 节点可选增加路线、前驱、合流、排序和当前位置字段。所有字段位于既有 JSON 数据中，是向后兼容扩展，无需破坏性 SQL 迁移；Supabase 仍通过现有用户隔离 JSONB 表和 RLS 同步。

## 当前限制与后续扩展

- 当前通过详情/节点抽屉编辑，甘特条不支持拖拽改期，避免制造未持久化的假交互。
- 路径显示顺序来自 `displayOrder`，暂未提供拖动排序。
- 依赖目前显示计数与详情信息；大规模网络可继续增加依赖连线避让与虚拟化。
- 目标编辑表单尚未暴露全部新元数据，但旧数据与未来字段会被 normalize 流程保留。
- 权限沿用现有本地/云同步边界；只读共享空间尚未实现。

## 实现前审计记录

- 入口位于 `LifeMapPage`，内部 `LifeOSPlanner` 维护 NOW、Planning、Life Map、Timeline 四视图；Life OS 节点、依赖、资源、事件和计划此前存放于版本化 localStorage key。
- 目标与任务通过 `linkedTaskIds` / `linkedGoalIds` 关联；Planning 接受方案后写入真实 Task，任务完成会记录执行事件并触发小范围重规划。Roadmap 是独立的目标路线草稿。
- 项目已有本地 vendor `@xyflow/react`，未使用日期或拖拽库；本次继续用它实现 Path Map 的平移、缩放和适应画布，日期计算集中在轻量 adapter，未新增依赖。
- 云端 `tasks` / `goals` 使用 JSONB，RLS 按 `auth.uid() = user_id` 隔离；因此可选字段可安全增量同步，不需要执行根目录破坏性重建脚本。
- 复用了现有白色卡片、圆角、阴影、红色强调、按钮、下拉框、详情抽屉及响应式横向滚动语言。
- 开始工作时 `git status --short --branch` 显示工作分支 `work` 且无未提交文件，未覆盖用户修改。
