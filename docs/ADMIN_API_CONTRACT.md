# Admin API contract

The separate operator console calls authenticated `/api/admin` with an `action`. Reads include `users`, `user_detail`, `entitlement`, `ai_usage`, `applications`, `invites`, `account_controls`, and `audit`. Mutations include `grant_entitlement`, `revoke_entitlement`, `create_invite`, `disable_invite`, `review_application`, `set_account_control`, `unban`, `grant_quota`, `reset_quota`, and `set_feature_flag`.

The server resolves `admin_roles`; email comparisons are never authorization. Owner/admin mutations append an `admin_audit_log` row and return `X-Request-Id`. No admin browser client receives service-role access.

## Command authority and retries

Send a valid UUID `X-Request-Id` and retain it for retries of the same submitted command. A missing ID is generated by the server; use a new ID for a new intentional command. The authenticated actor is resolved server-side, never from a submitted user/actor field.

All ten mutation actions call service-only `beta_admin_command(actor, request, action, input)`:

- The database rechecks enabled admin/owner authority and actor account controls on every call, including replay. Feature flags require owner authority.
- Canonical JSONB action/input is SHA-256 hashed before defaults/randomness are resolved. A transaction-scoped actor/key advisory lock plus composite primary key prevents duplicate commits.
- Same actor/key/action/payload returns the original committed domain result, including original dates/IDs/effective entitlement snapshot. No new mutation/audit occurs and later state is not reverted.
- Different action/payload returns HTTP 409 with `code: IDEMPOTENCY_KEY_REUSED`. Different actors have independent namespaces. JSON object key order is immaterial; omitted fields versus explicit null are distinct submissions.
- Mutation, audit, receipt and any private invite replay result are one transaction. A failure leaves no receipt and the same key can be retried after the fault is repaired. No separate HTTP audit write follows a mutation.
- Prior mutation workers remain internal SQL helpers. EXECUTE is revoked from application roles, including service_role, so they cannot bypass command receipts. Only the dispatcher is the supported mutation RPC.

Invite disable and application review lock the target row and audit before/after state. Review accepts only `pending`, `shortlisted`, `approved`, `rejected`, `invited`, `registered`, `expired`; actor and reviewed_at are database-authored. Missing target returns 404. Invite before/after/audit/general receipt never includes plaintext code or code_hash.

## Sensitive invite replay

Creation stores the plaintext replay result only in `vd_admin_private.invite_command_results`, not the general receipt, audit or exposed Data API schema. PUBLIC/anon/authenticated/service_role have no schema usage or table privileges. Only the SECURITY DEFINER dispatcher can recover the exact matching actor/key after rechecking current authority. Responses remain `Cache-Control: no-store`; listing invites does not expose the code. Database owners and backups remain trusted and must handle this private table as sensitive. Results are retained to preserve exact retry semantics; expiry/retention/key-management policy is an operational follow-up, not an excuse to put codes in audit logs.

## Supported quota tiers and usage costs

Closed Beta supports Free + Plus only (`vd.plus` entitlement union). Pro is reserved but unsupported: its seed is disabled and a constraint prevents enabling it in this release. A future Pro release requires an explicit entitlement/policy migration. Reset is still finite compensation for the authoritative current policy period, not permanent/unlimited allowance.

AI feature is selected from the canonical contract: goal_roadmap -> goal_roadmap; review_history/legacy_review -> review; plain pressure_analysis stays pressure_analysis; goal_decompose stays goal_decompose.

`ai_usage` returns `cost_status`, nullable `estimated_cost_minor`, `currency`, `pricing_version`, actual provider/model and input/cached/output tokens. Operators must show unknown as 未知, never coerce null to zero; `cost_status=estimated` with cost 0 is an explicit priced zero. These are estimates, not provider billing evidence.

Optional server-only `VD_AI_PRICING_JSON` is versioned `{version, currency, models: {provider: {model: rates}}}`. Rates are `inputMinorPerMillion`, `cachedInputMinorPerMillion`, `outputMinorPerMillion` in currency minor units per million tokens (nonnegative numbers, up to six decimal places). Configure only verified tariffs for the actual returned model. No default guessed DeepSeek prices are supplied. Missing/invalid/unmatched configuration or insufficient/invalid usage evidence yields unknown. Input cache hits are subtracted from ordinary input, charged at the cache rate, and the total is rounded upward once to a minor unit. Rates changing requires a new version; historical finalized estimates retain their version. Synthetic test rates are not tariffs.
